# Phase 2: fixes from the end-to-end skill test

## Why

A fresh agent ran the installed skill on policy-tracker using only the skill files and the real MCP server. The run worked end to end, and it surfaced five rough edges. The transcript and tool outputs are in `<scratchpad>/e2e/`.

## Fixes

1. **`sessionSays` should quote what the talk covers, not its marketing opener.**
   - Today the quote is the first unlisted sentence that names the concept. It is often the abstract's opener, e.g. "Amazon EventBridge simplifies event routing for distributed applications."
   - Among the sentences that qualify, prefer one that says what the attendee will learn, build or see. Cue words include: learn, build, explore how, discover how, walk through, dive into, see how, we'll show, you'll, demo, hands-on, deep dive, patterns for, best practices.
   - Fall back to the current first match when no sentence has a cue.
   - Keep everything else as it is: verbatim text, ellipsis trimming, listing rules, the fallback order and the omission rules.
   - Report how many of the 787 candidates' quotes change on the 7 eval profiles. Read 30 of them and confirm they're more informative.
2. **Time conflicts must not be guessed.**
   - Match and focus offerings have a start time but no end, so the e2e agent judged "none overlap" from start times alone.
   - Add `lengthMinutes` and an `endTime` (computed from start + length) to each offering, wherever offerings are emitted. If the catalog length is missing, omit both fields.
   - SKILL.md and workflow.md must tell the agent to use `plan_schedule` for any conflict or "can I attend both" question, and never to infer overlap itself.
   - Check that the MCP 30 KB budget still holds.
3. **Remove the profiling guide's dead-end pattern names.**
   - `reference/profiling.md` tells profilers to spell a topic-like pattern with the catalog topic's exact spelling ("Security & Identity"), and it recommends `api`. The map then reports both as having no sessions.
   - Every pattern name the guide recommends must be one the lenses and the map can match: it must have a phrase entry in `concepts.ts`, or be a supported gap or next-level source.
   - Remove the "use the topic's spelling" instruction. A user's topical interests belong in `interests`; the profiler doesn't invent them.
   - Add a content test that extracts every recommended pattern name from the guide and asserts each one is matchable. It must fail if someone adds an unmatchable name.
4. **The map should say why some services aren't shown.**
   - Platform services (`PLATFORM_SERVICES`: S3, KMS, CDK, CloudWatch, IAM, …) are left out of the map by design, but other supporting services such as SQS, WAF and SNS are shown. To the e2e agent this looked inconsistent.
   - The text map gets one line, e.g. "Not shown: S3, KMS, CDK (platform services nearly every workload uses; they don't narrow sessions)", listing only the platform services this profile actually has.
   - JSON gets `omittedPlatformServices: string[]`.
   - Supporting services stay listed, as now.
5. **Sign-in shouldn't be needed to browse.**
   - The skill's flow starts with `status` and sign-in.
   - Mapping and matching only need a synced catalog. Sign-in is needed only for `catalog_sync` and the schedule, favorite and reservation tools.
   - `status` must return a non-error result when no one is signed in, reporting `signedIn: false` and the catalog state. Check the tool's current contract and its tests first. If `isError` is pinned on purpose, explain why before changing it.
   - Update SKILL.md so that:
     - when the catalog is present, the agent profiles, maps and matches without signing in;
     - it signs in only when it needs to sync or touch the schedule;
     - it still runs `auth login` itself when sign-in is needed, as now.

## Rules

- TDD with sabotage on every change.
- No ranking changes. Candidate order and membership must be byte-identical to main on the 7 eval profiles under all 4 lenses, apart from the fields this plan adds or changes (`sessionSays`, offering end times, `omittedPlatformServices`). Diff with those fields stripped.
- Domain logic stays in `src/**` domain modules; adapters stay thin. Keep `exactOptionalPropertyTypes` happy.
- Update the README, workflow.md, SKILL.md and the pinned content tests.

## Results

Five commits on `phase-2/e2e-fixes`; `npm run check` is green on each, 1579 tests at the end (1547 on main).

1. **sessionSays** (8973f62). `MatchSite` carries the other abstract places that name the concept (`others`); `quoteSite` takes the first whose sentence has a learn/build/see cue and falls back to the first match. All three sources set it (all/explain concepts, fix/next-level signals). Over the 787 candidates in 4 lenses x 7 profiles (limit 100), 196 quotes changed. I read 30 spread across the 196: 26 are more informative (they say what the attendee will do: "In this workshop, build agentic orchestration using AWS Lambda durable functions and MCP tools." replaces "AI agents are powerful, but production workloads need more than an LLM and a prompt."), 2 are about equal, 2 are weaker: a negated cue ("This isn't a best-practices talk - it's a field guide to building resilience...") and an incidental "building agents". No cue handles negation; left as is.
2. **Offering end times** (4addaec). Offerings carry `lengthMinutes` and `endTime` (start plus length, the same local time; `endDate` only past midnight); both are omitted when the catalog has no length, and `endTime` when there is no start time. The CLI text shows `10:00-11:00`. Skill and workflow say overlap and "can I attend both" are `plan_schedule` questions. MCP budget holds: the largest of 28 match responses (7 profiles x 4 lenses, limit 50) is 30,497 bytes, under 30,720.
3. **Profiling guide** (f2e4aa9). Removed the topic-spelling exception, `Security & Identity` as a pattern, and `iac-terraform`/`iac-cloudformation`. `api` is kept: it has a phrase entry in `concepts.ts`; the map's "no sessions" for it was the catalog, not an unmatchable name. A content test extracts the guide's starting vocabulary, curated phrase list and worked-example patterns and asserts each has a phrase entry or is a gap or next-level source; it goes red if `iac-terraform` or `Security & Identity` is put back.
4. **Platform services** (64e579d). `omittedPlatformServices` (short names, profile order) in the map JSON, and a "Not shown: S3, KMS, CDK (platform services nearly every workload uses; they don't narrow sessions)" line in the text map, only when the profile has some.
5. **No sign-in to browse** (32fc876). `status` was pinned to `isError` by amendment 3 only so the agent would learn it could run `auth login` itself; that wording moved into a `signIn` note on a non-error `{ signedIn: false, catalog, signIn }` result (also for unreadable tokens). The skill profiles, maps and matches without signing in and signs in only to sync or touch the schedule.

**Regression.** With `sessionSays`, `lengthMinutes`, `endTime`, `endDate` and `omittedPlatformServices` stripped, candidate order and membership match main (162d297) on all 4 lenses, the map and the recorded focus picks for the 7 profiles: 39/39 identical.

**Sabotage.** 4 + 7 + 12 + 10 + 11 mutants, each red on a named test after four fixes (an unused dedupe removed, a test for 24 h+ sittings and for `HH:MM:SS`, and a test for an out-of-range alternate place).
