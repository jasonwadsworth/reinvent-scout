# Phase 2: an `all` lens worth defaulting to

## Why

`all` is the default lens; the skill uses it unless the user asks for another. On policy-tracker, its top results were:

- a sponsored vendor talk (SEC218-S, "Extend AWS WAF to the APIs your AI agents call (sponsored by Wallarm)");
- a Terraform audit talk matched only by catalog tags (COM302);
- CloudFront and WAF talks.

It is still the original BM25+IDF matcher. It has none of the rules that fixed the other three lenses:

- tags and listed services count as signals;
- IDF favours the profile's rarest term over its central ones;
- sponsored and news talks rank like any other;
- there is no admission bar, so every session with any overlap is a candidate.

## What `all` means

`all` answers: "Which sessions are about the technologies and architecture this code is built on?"

- Any level and any format.
- Unlike `explain`, it doesn't need to be introductory.
- Unlike `fix` and `next-level`, it doesn't need a gap or a path.

## Target behavior

1. **Admission: the session must be about one of the profile's concepts.**
   - Concepts are the same as `explain`'s: core services and non-gap patterns, excluding `PLATFORM_SERVICES`, with supporting services at half weight.
   - A concept counts when it appears in the title, or twice in the abstract outside a listing, or once in the abstract outside a listing plus a matching tag or listed service.
   - Tags or listed services alone never admit.
   - Reuse `explain.ts`'s concept matching (service-name variants, pattern phrase map, listing detection). Extract it rather than copying it.
2. **Excluded:** partner-only bootcamps and certification/exam sessions, the same rules `explain` uses.
3. **Demoted:**
   - Sponsored sessions (`-S` codes or "(sponsored by …)"), news/launch talks, and customer-story talks are not excluded, since an advanced user may want them.
   - They rank after every non-demoted session with the same concept coverage.
   - Each carries a `demoted` reason saying why, and the `why` summary mentions it.
4. **Ranking prefers the code's central, well-covered concepts over rare terms.**
   - Order by, in sequence:
     - (a) the sum of the matched concepts' centrality (distinct citing files, supporting at half weight);
     - (b) the strongest match strength (title > repeated abstract > corroborated abstract);
     - (c) the number of distinct matched concepts;
     - (d) the existing BM25 relevance, only as the final tiebreak.
   - Make the order lexicographic or tiered, not additive with tunable weights.
5. **Coverage.** No single concept may take more than 3 of the top 10 unless fewer than 4 concepts have any admitted session. Keep the rest in order after the top 10.
6. **`why` keeps working.** The `all` summary names the matched concepts actually used for admission. `sessionSays` quotes the admitting mention.

## Grading rubric (decided up front; the reviewer uses the same one)

Grade each of the top 10 for a developer on this codebase:

- **GENUINE:** the session's primary subject is a technology or architecture this code substantially uses, and a developer on this code would plausibly choose to attend.
- **WEAK:** the session is related, but its primary subject is something else, or it's a customer story, launch recap, or vendor pitch whose subject is on-stack.
- **NOISE:** a tag-only or list-only overlap, or an off-stack subject.

## Targets

Measure on the 7 eval profiles (the `gaps/` copies). Tuning set: hallway, kirocrew, adaptative-http, policy-tracker, career-ops. Holdout: conformity, tracking.

- **Baseline first.** Grade the current top 10 for each profile before changing anything.
- **Precision.** At least 70% GENUINE on tuning, on the independent reviewer's grades. Report the holdout separately.
- **Coverage.** Among each profile's top 5 concepts by centrality, at least 3 appear in the top 10, or have no admitted session at all (report which).
- **career-ops.** Returns only sessions about its evidenced concepts, or nothing.
- **No regressions.**
  - `explain`, `fix` and `next-level` output are byte-identical to main on all 7 profiles. The shared-matcher extraction must not change them.
  - The MCP 30 KB budget holds at the maximum limit.
  - CLI `--json` equals MCP.
