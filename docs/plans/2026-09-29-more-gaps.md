# Phase 2: more evidence-backed gaps for the Fix lens

## Why

Fix has 7 gap rules, about one per Well-Architected pillar. Many real, code-visible problems have
no rule. A gap earns a rule only if both of these hold:

- (a) a profiler can prove it from code with a file/line citation;
- (b) the catalog has sessions that are really about fixing it.

## Candidates

For each candidate, first check (b) on the real catalog (the catalog-only copy in `lens-home`):
there must be at least 3 sessions whose title, or repeated unlisted abstract text, is about the
remedy. Drop any candidate that fails, and record why.

| Gap | Pillar | Code evidence (examples) |
|---|---|---|
| `gap-no-tracing` | Operational Excellence | No X-Ray/OpenTelemetry/Powertools tracer on Lambda/ECS/API |
| `gap-unstructured-logging` | Operational Excellence | `console.log`/`print` strings, no JSON logger |
| `gap-no-ci` | Operational Excellence | Deployed infra but no pipeline (no workflows/buildspec/pipeline stack) |
| `gap-no-timeouts` | Reliability | Default Lambda timeouts on API paths, HTTP/SDK clients without timeouts |
| `gap-no-retry-backoff` | Reliability | Hand-rolled retry loops without backoff/jitter, retries disabled |
| `gap-no-backups` | Reliability | DynamoDB without point-in-time recovery, RDS backup retention 0, no AWS Backup plan |
| `gap-single-az` | Reliability | RDS/ElastiCache without Multi-AZ, a single-subnet/AZ ECS service |
| `gap-no-idempotency` | Reliability | At-least-once consumers (SQS/EventBridge/streams) with side effects and no idempotency key |
| `gap-no-encryption` | Security | S3/SQS/SNS/RDS/EBS without encryption at rest, or with encryption disabled |
| `gap-secrets-in-code` | Security | Hard-coded keys or passwords, secrets in plaintext environment variables |
| `gap-public-exposure` | Security | S3 public access not blocked, security group 0.0.0.0/0 on non-HTTP ports, unauthenticated API routes |
| `gap-no-waf` | Security | A public API/CloudFront/ALB with no WAF association |
| `gap-no-caching` | Performance Efficiency | A hot read path with no cache layer (CloudFront/ElastiCache/DAX/API cache) |
| `gap-no-log-retention` | Cost Optimization | Log groups with no retention (never expire) |
| `gap-no-storage-lifecycle` | Cost Optimization | S3 buckets with no lifecycle rules or tiering |
| `gap-no-graviton` | Sustainability | Lambda/ECS/EC2 on x86 with no arm64 choice |

## Per-gap work (each surviving candidate)

1. **Rule** in `lens-signals.ts`:
   - a specific remedy phrase, following the alarms lesson (no bare common words);
   - `minStrength` where it's justified;
   - remedy or tool services where the remedy is a tool the profile won't list (for example
     WAF, Backup, X-Ray).
   Use the existing mechanisms (list detection, stack-fit gate, remedy path). Don't add a new
   mechanism unless a candidate can't work without it; if you add one, say so.
2. **Profiling guide** (`reference/profiling.md`):
   - the gap's name and pillar;
   - exactly what counts as evidence;
   - what does NOT count, covering partial scope and "switched off";
   - a row in the rules table.
   A guide entry must be specific enough that two profilers would agree.
3. **Tests.** Synthetic `IndexRecord`s. Admit on a real remedy session; reject a passing mention, a
   listing, a common-word false positive, and an off-stack session. Sabotage the phrase and confirm
   a named test goes red.

## Evaluation

The 7 eval profiles don't record the new gaps yet. For each profile:

- re-inspect its repos read-only, using the new guide entries only;
- add the new gap patterns with real citations, and nothing else;
- save the result as `<name>-profile-gaps.json` in the scratchpad (don't overwrite the originals);
- keep the original gaps unchanged.

Then run `fix` on all 7 and grade every candidate from the new rules GENUINE/WEAK/NOISE.

Tuning set: hallway, kirocrew, adaptative-http, policy-tracker, career-ops. Holdout: conformity,
tracking.

## Targets

- **Precision:** the new rules together reach at least 70% on the tuning set and on the holdout.
  A rule that can't get its own noise under 50% on the tuning set is dropped. Say so; don't
  weaken the target.
- **No regressions:** the existing 7 rules' output on the original profiles is unchanged (diff it),
  unless a shared mechanism changed, in which case explain the difference.
- **Correct empties:** career-ops still returns nothing under `fix`.
- **Report:** which candidates shipped, which were dropped and why, and how many of the 7 profiles
  each new gap fired on.

## Rules

- TDD with sabotage.
- No session codes or profile special cases in `src`.
- `npm run check` green for every commit.
- Commit per gap or small group of gaps.

## Out of scope

- The explain lens (another branch is changing `lens.ts`, `match.ts` and "The explain lens" section
  of `profiling.md`; don't touch them).
- Next-level paths.

Rule design: specific phrases only (no bare "tracing", "pipelines", "backup", "cache", "firewall"), default strength 2, and the existing remedy-service path (AWS Distro for OpenTelemetry; CodePipeline, CodeBuild, CodeDeploy; EC2 - Graviton). The catalog has no X-Ray service, so tracing uses the OpenTelemetry one, like the Amazon SES note last round.

**One new mechanism (flagged).** `aiProfileOnly` on a rule: a session tagged Agentic AI or Generative AI is admitted only for a profile that has an `agentic` or `genai-single-call` pattern. The first run of the six rules put agent-security and agent-remediation talks (COM328, NET321, NET334, NET329, SEC325) on non-AI profiles. It is general (tag-based, no session code) and is set on the new rules only, so the older rules' output cannot change. `reverse`, which already existed, now also excludes "migrating from a third-party WAF" for WAF (later dropped with the rule) and `gap-no-ci` no longer matches "deployment pipelines" (blue/green strategy talks, CON318).
